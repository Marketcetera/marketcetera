# Internationalization (I18N) Guide for Marketcetera

This guide explains how to use the internationalization (I18N) and localization (L10N) framework in the Marketcetera platform.

## Overview

Marketcetera uses a custom internationalization framework based on Apache Commons i18n that provides:

1. Parameterized messages stored in external resource files
2. Support for multiple locales and language translations
3. Integration with SLF4J logging
4. Consistent error message formatting across the application

The main components of the framework are:

- `I18NLoggerProxy`: A logger that supports internationalized messages
- `I18NMessageProvider`: Maps message IDs to text patterns defined in resource files
- `Messages` interface: Defines message constants for each module/package
- Resource properties files: Store actual message text in key-value format

## Setting Up I18N in a Module

### 1. Create a Messages Interface

Each module or package should have a `Messages` interface that defines all internationalized messages:

```java
package org.marketcetera.yourmodule;

import org.marketcetera.util.log.I18NLoggerProxy;
import org.marketcetera.util.log.I18NMessage0P;
import org.marketcetera.util.log.I18NMessage1P;
import org.marketcetera.util.log.I18NMessage2P;
import org.marketcetera.util.log.I18NMessageProvider;
import org.marketcetera.util.misc.ClassVersion;

@ClassVersion("$Id$")
public interface Messages {
    /**
     * The message provider.
     */
    static final I18NMessageProvider PROVIDER = 
        new I18NMessageProvider("yourmodule");  

    /**
     * The logger.
     */
    static final I18NLoggerProxy LOGGER = 
        new I18NLoggerProxy(PROVIDER);

    /*
     * The messages.
     */
    static final I18NMessage0P INITIALIZATION_FAILED = 
        new I18NMessage0P(LOGGER, "initialization_failed");
        
    static final I18NMessage1P CONNECTION_ERROR = 
        new I18NMessage1P(LOGGER, "connection_error");
        
    static final I18NMessage2P DATA_RECEIVED = 
        new I18NMessage2P(LOGGER, "data_received");
}
```

The message provider ID "yourmodule" should match the base name of your properties file (without the `_messages.properties` suffix).

### 2. Create a Properties File

Create a resource file in `src/main/resources` with the name `yourmodule_messages.properties`:

```properties
# Must be encoded in ISO-8859-1
# Use unicode escapes (\uxxxx) for non-ISO-8859-1 characters

initialization_failed.msg=Module initialization failed.
connection_error.msg=Failed to connect to {0}.
data_received.msg=Received {0} records for {1}.
```

Note that each message key must end with `.msg` and should match the lowercase string ID used in the `Messages` interface.

### 3. Using the Messages in Code

```java
package org.marketcetera.yourmodule;

import org.marketcetera.util.log.I18NBoundMessage1P;

public class YourClass {
    public void connect(String server) {
        try {
            // Connection logic...
        } catch (Exception e) {
            // Log with internationalized message
            Messages.CONNECTION_ERROR.error(this, e, server);
            throw new ConnectionException(
                new I18NBoundMessage1P(Messages.CONNECTION_ERROR, server), e);
        }
    }
    
    public void processData(int recordCount, String source) {
        // Informational log with internationalized message
        Messages.DATA_RECEIVED.info(this, recordCount, source);
    }
}
```

## Message Type Reference

The framework provides different message classes depending on the number of parameters:

- `I18NMessage0P`: Message with no parameters
- `I18NMessage1P`: Message with 1 parameter
- `I18NMessage2P`: Message with 2 parameters
- `I18NMessage3P`: Message with 3 parameters
- `I18NMessage4P`: Message with 4 parameters
- `I18NMessage5P`: Message with 5 parameters
- `I18NMessage6P`: Message with 6 parameters
- `I18NMessageNP`: Message with a variable number of parameters

## Logging Levels

Use the appropriate logging level for different types of messages:

```java
// Error level
Messages.ERROR_MESSAGE.error(this, exception, param1);

// Warning level
Messages.WARNING_MESSAGE.warn(this, param1, param2);

// Info level
Messages.INFO_MESSAGE.info(this, param1);

// Debug level
Messages.DEBUG_MESSAGE.debug(this, param1, param2);

// Trace level
Messages.TRACE_MESSAGE.trace(this, param1, param2, param3);
```

## Supporting Multiple Languages

To add support for additional languages, create translated properties files with locale suffixes:

- `yourmodule_messages_fr.properties` (French)
- `yourmodule_messages_de.properties` (German)
- `yourmodule_messages_ja.properties` (Japanese)

Example of a French translation file:

```properties
# French translation
initialization_failed.msg=L'initialisation du module a échoué.
connection_error.msg=Échec de la connexion à {0}.
data_received.msg=Reçu {0} enregistrements pour {1}.
```

## Best Practices

1. **Keep messages external**: Never hardcode user-facing messages in Java code.

2. **Use message parameters**: Insert variable data using parameters instead of string concatenation:
   ```java
   // Good
   Messages.CONNECTION_ERROR.error(this, host);
   
   // Bad
   logger.error("Failed to connect to " + host);
   ```

3. **Descriptive message keys**: Use descriptive key names that reflect the message purpose.

4. **Ensure message key uniqueness**: Keep keys unique across all modules to avoid confusion.

5. **Include context in messages**: Make sure messages provide enough context for both users and developers.

6. **Document parameter meanings**: Include comments in the properties file to explain parameter usage.

7. **Verify message text**: Ensure messages are grammatically correct and appropriately formatted.

8. **ISO-8859-1 encoding**: Remember that properties files must be encoded in ISO-8859-1, using Unicode escapes when needed.

## Exceptions with I18N Messages

When throwing exceptions with internationalized messages, use the `I18NBoundMessage` classes:

```java
// Create a bound message with parameters
I18NBoundMessage2P boundMsg = new I18NBoundMessage2P(
    Messages.VALIDATION_ERROR, fieldName, maxLength);
    
// Throw exception with the bound message
throw new ValidationException(boundMsg);
```

Exception classes should accept `I18NBoundMessage` parameters in their constructors.

## Testing Messages

Use the `MessagesTest` pattern to verify that all messages in a `Messages` interface have corresponding entries in the properties file:

```java
package org.marketcetera.yourmodule;

import org.junit.Test;
import org.marketcetera.util.l10n.MessageComparator;
import org.marketcetera.util.test.TestCaseBase;

public class MessagesTest extends TestCaseBase {
    @Test
    public void messagesMatch() throws Exception {
        MessageComparator comparator = new MessageComparator(Messages.class);
        assertTrue("Message keys don't match resource", comparator.getDifferences().isEmpty());
    }
}
```
